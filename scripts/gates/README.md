# `scripts/gates/` — 기계가 막는 것들

> 🗓️ 2026-09-16 신설. 그전까지 게이트 11개가 `scripts/` 직하에 **도구 스크립트와 섞여** 있었다.
> 규칙 정본 = **`docs/QUALITY_GATES.md`**. 여기는 **어디에 무엇이 있는지**만 말한다.

## 폴더가 곧 분류다

| 폴더 | 무엇을 지키나 | 언제 |
|---|---|---|
| `doc/` | **문서·기록 규약** — 배치·`doc-meta`·스냅샷 짝·포트폴리오 근거·메모리 인덱스 | `pre-push` |
| `code/` | **코드·아키텍처** — 레이어 계약 · 폐기 어휘 · `QA-##` 앵커 | `pre-push` (+ 레이어는 CI) |
| `commit/` | **커밋 메시지** — 트레일러 금지 · 제목 위생 | `commit-msg` |
| `tooling/` | **도구 자신의 위생** — UTF-8 출력 방어 | `pre-push` |

```
scripts/gates/
├── _root.py          ← 저장소 루트를 "깊이"가 아니라 "표식(pyproject.toml)"으로 찾는다
├── doc/      check_doc_filing · check_doc_meta · check_plan_archives
│             check_portfolio_sync · check_memory_index
├── code/     check_layers · check_comment_staleness · check_anchors
├── commit/   check_commit_trailers · check_commit_subject
└── tooling/  check_utf8_guard
```

### `_root.py` 가 따로 있는 이유

재편 전에는 각 게이트가 `Path(__file__).parents[1]` 로 루트를 **깊이로** 셌다.
폴더를 한 단계 나누자 **전부 깨졌다.** 깊이를 세면 폴더를 옮길 때마다 또 깨진다 —
그래서 `pyproject.toml` 이 있는 첫 조상을 찾는다. 못 찾으면 **예외를 던진다**(추측한 경로로
검사를 계속하면 대상 0건을 초록으로 보고하게 된다).

---

## 두 가지 공통 규칙

### 1. 🔴 fail-closed — *"검사 대상이 없다"* ≠ *"문제가 없다"*

대상을 못 모으면 **실패**한다. 구분하지 못하면 게이트가 **자기가 죽었다는 것을 초록으로 보고**한다.

> **실제로 그 일이 이 재편에서 일어났다.** `check_utf8_guard` 가 `glob("*.py")`(직하만) 라서
> 게이트 11개가 통째로 범위에서 빠졌는데 **"1건 전부 방어됨"** 이라고 초록을 냈다.
> → `rglob` + **하한선 검사**(`MIN_EXPECTED`)를 넣었다. **0건만이 아니라 줄어든 것도 실패다.**

같은 결의 함정을 `check_plan_archives` 도 갖고 있었다(완료기록을 하위 폴더로 옮기는 순간 0건 수집).

### 2. 침묵 금지 — 통과할 때도 **센 것을 말한다**

```
✅ 문서 배치 — 직하 11종 규약 준수 · 축 폴더 75건 이름 정합.
✅ PLAN 스냅샷 정합 — 완료기록 21건 · PLAN 참조 18쌍 · 빠진 스냅샷 0.
```

침묵은 *"문제없음"* 과 *"안 돌았음"* 을 구분하지 못한다.
2026-09-16 실측에서 게이트 3종이 통과 시 **아무것도 출력하지 않고 있었다.**

## 차단 / 보고를 가르는 기준

> **정밀도가 높고 지금 고칠 수 있는 것만 차단한다.**
> 정밀도 낮은 게이트는 사람이 끄고, 그러면 **옆의 정확한 게이트까지 죽는다**
> (`docs/QUALITY_GATES.md` §2-1).

실제 사례 — `check_comment_staleness` 의 *주석 속 식별자 실재 검사*는 표본 검출률 86% 였지만
저장소 전체에서 오탐 78건이 나와 **게이트에서 빼고 보고 전용으로 강등**했다.

---

## 새 게이트를 만들 때

1. **검출률을 먼저 잰다.** 80% 미만이면 게이트 말고 보고로.
2. **결핍 주입으로 무장을 확인한다**(절차 = `docs-private/study/2026-09-16_deficiency-injection-study.md`).
   초록은 무장의 증거가 아니다 —
   위반을 하나씩 심어 각각 빨개지는지 본다.
3. ⭐ **음성 대조도 같이 돌린다.** 결핍 주입은 *"잡아야 할 걸 잡나"* 만 묻는다 —
   **`return 1` 만 하는 게이트도 만점**이다. *"이건 정상이니 통과해야 한다"* 표본
   (결함과 **가장 닮았지만 정상인 것**)을 같이 넣어 **과잉 차단**을 잰다.
   과잉 차단하는 게이트는 사람이 끄고, 그러면 **검출률이 0** 이 된다.
4. **fail-closed 분기**를 넣는다(대상 0건·줄어듦·파서 깨짐).
   🔴 **하위 검사마다 각각** — 전체 대상이 많아도 *특정 검사만* 0건일 수 있다
   (문서 36건을 읽으며 계승 링크를 0건 본 상태). 하위 검사별 **바닥값**을 둔다.
5. **성공 출력 한 줄**에 센 것을 적는다 — **하위 검사별 건수까지**.
6. `stdout`·`stderr` **둘 다** `reconfigure` 한다 — 한쪽만 하면 다른 쪽이 cp949 에서 죽는다(D36).
7. `.pre-commit-config.yaml` 에 등록하고 **실제로 도는지** 확인한다
   (훅 미설치로 로컬 게이트가 안 돌던 전례 = 대장 D12).

## 전수 점검 실적 (2026-09-20)

**게이트 11종을 모두 다시 재고 세 가지를 맞췄다.** 규칙은 있었는데 기계가 따라오지 않은 자리들이다.

| | 이전 | 지금 |
|---|---|---|
| **바닥값**(줄어든 것도 실패) | 3/11 | **11/11**(해당 없는 commit 2종 제외 시 9/9) |
| **음성 대조 표본**(docstring) | 0/11 | **11/11** |
| **fail-closed** | 8/11 | **11/11** |

🔴 **가장 위험했던 자리 = `check_layers`.** `lint-imports` 는 계약이 **하나도 없어도**
`Contracts: 0 kept, 0 broken.` 을 찍고 **exit 0** 이다. `pyproject.toml` 의 계약 섹션이 지워지면
**아무것도 검사하지 않은 채 초록**이 됐다. 지금은 출력을 파싱해 **계약 수 바닥값**을 건다.

검증: **결핍 주입 7/7**(대상을 줄이는 방향으로 주입) · commit 게이트 **음성 대조 포함 5/5**.

> ⚠️ **바닥값은 손으로 올린다.** 대상이 늘면 그때 올리는 것이 **의식적인 결정**이 된다.
> 자동으로 따라가게 만들면 *"줄었다"* 를 영영 못 잡는다.

## 게이트를 은퇴시킬 때

**전제가 죽었는지** 먼저 본다. 회피하려고 지우는 것과 다르다.

`canon-sync` 는 *"축 폴더가 정본보다 새로우면 정본이 낡은 것"* 으로 판정했는데,
새 배치 규약에서 축 폴더는 **정본의 옛 판이 내려앉는 곳**이라 **정의상 언제나 과거**다
→ 영원히 초록을 내는 **통과 기계**가 됐다. 그래서 은퇴시키고 `check_doc_meta` 의
`affects` 절 diff 로 대체했다. 사유는 `.pre-commit-config.yaml` 에 주석으로 남아 있다.

> ⚠️ **겹치지 않는 게이트를 "정리"라는 이름으로 지우지 않는다.** `plan_archives`·`portfolio_sync`
> 는 새 게이트와 **다른 축**을 본다 — 실제로 문서 대이동 직후 `portfolio_sync` 가
> 깨진 근거 참조 2건을 잡았다.
